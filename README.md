# FunnyMoney — игровой финансовый тренажёр

FunnyMoney (рабочее название продукта — «Питомец Финни») — мобильный прототип для детей 7–11 лет. Ребёнок заботится о виртуальном питомце, получает игровую валюту, планирует бюджет, выбирает между обязательными и желаемыми покупками, откладывает деньги на цель и сразу видит последствия решений.

Это не банковское приложение: в проекте нет реальных платежей, рекламы, финансовых рекомендаций и обязательной регистрации. Основной игровой цикл работает офлайн.

## Быстрый запуск веб-версии

Требования: Node.js 20+ и npm 10+.

```bash
npm ci
npm run dev
```

Откройте адрес Vite, обычно `http://localhost:5173`. Для production-проверки:

```bash
npm run build
npm run preview
```

Полезные проверки:

```bash
npm run test:economy  # бюджет, покупки, накопления, развитие и события
npm run lint          # проверка исходников
```

## Сборка Android APK

1. Установите Android Studio, Android SDK и JDK 21.
2. Установите зависимости и соберите web-часть: `npm ci && npm run build`.
3. Синхронизируйте web-ресурсы: `npx cap sync android`.
4. Соберите debug APK: `cd android && ./gradlew assembleDebug`. Файл появится в `android/app/build/outputs/apk/debug/`.
5. Для конкурсной сдачи используйте подписанную release-сборку Android Studio или Gradle. Параметры приложения: `applicationId com.funnymoney.app`, `versionName 1.0`, `versionCode 1`. Ключ подписи не хранится в репозитории.

Приложение фиксировано в портретной ориентации. Целевая проверка — Android 8.0+ и ширина от 360 dp. Перед сдачей release APK необходимо проверить на физическом Android-устройстве с 3 ГБ ОЗУ и указать модель/версию Android в отчёте.

## Демонстрационный сценарий комиссии

Рекомендуемый прогон соответствует Приложению А ТЗ: запуск и знакомство; локальный профиль; выбор питомца и имени; стартовый баланс и цель; распределение суммы по обязательному, желаемому и накоплениям; задание и награда; обязательная и необязательная покупки; отказ при нехватке денег; выбор цели и пополнение копилки; сравнение плана и факта; следующий период; закрытие и повторный запуск; раздел для взрослого и сброс тестового профиля.

На desktop-предпросмотре dev-панель справа позволяет быстро выбрать период 1–5 и подготовить результат периода. Это инструмент проверки, в production Android-интерфейс не попадает.

## 1. Назначение, аудитория и границы

Целевая аудитория — дети 7–11 лет, которые осваивают простые суммы, различают «нужно» и «хочется» и учатся копить на понятную цель. Продукт формирует навык через действие и последствие, а не через длинную лекцию.

В MVP намеренно отсутствуют банковские счета, реальные деньги, платежи, реклама, платные подписки, публичные чаты, рейтинги с персональными данными, внешние ссылки для ребёнка и обязательный сервер.

## 2. Архитектура и технический стек

```text
Android APK (Capacitor) → WebView → React + TypeScript + Vite
  ├─ UI: src/pages, src/components
  ├─ Zustand stores: src/features
  ├─ Game Core: src/core (чистые правила экономики)
  ├─ Content: src/data (уроки, товары, события, периоды)
  └─ Storage adapter: Capacitor Preferences / localStorage fallback
```

Серверная часть и OpenAPI в MVP отсутствуют. Игровой цикл не требует постоянного подключения к сети. Логика экономики не зависит от React и проверяется отдельно от UI.

Основные каталоги: `src/core/` — расчёты; `src/features/` — игровые stores и компоненты; `src/pages/` — экраны; `src/data/` — контент; `src/services/` — хранение, bootstrap, звук и сессия; `src/assets/` — ассеты сборки; `design/` — макеты и исходники; `docs/` — решения; `android/` — Capacitor-проект.

## 3. Структура данных и сохранение

Профиль хранит игровое имя, персонажа, показатели питомца, инвентарь и настройки. Состояние периода содержит `id`, доступный баланс, план (`mandatory`, `optional`, `savings`), фактические расходы, накопления, флаги наград, статус и историю завершённых периодов. Задания и товары — типизированные записи в `src/data/` и не зашиты в JSX-компоненты.

Ключи локального хранилища имеют префикс `funnymoney:` и версию схемы. На Android запись идёт через `@capacitor/preferences`; веб-версия использует fallback. Очередь записи и bootstrap уменьшают риск потери состояния при переходах и перезапусках.

## 4. Правила и формулы игровой экономики

- План валиден, если три категории заданы неотрицательными суммами и `mandatory + optional + savings ≤ доступный баланс`.
- Покупка разрешена только при положительной цене, доступности товара и `кошелёк ≥ цена`; отрицательный баланс невозможен.
- Накопления переводятся отдельной подтверждённой операцией и не смешиваются с кошельком.
- Совпадение плана и факта: `100 × (1 − сумма абсолютных отклонений / сумма плана)`, от 0 до 100.
- Итог периода: `40` баллов за обязательное, `30%` от совпадения плана и `30` за регулярное накопление минимум 100 монет.
- Стадия питомца: 1 до 1 хорошего периода, 2 после 2, 3 после 4.
- Богатство на экране — процент от лимита периода, складывающий кошелёк и накопления; это учебная шкала, а не ограничение баланса.

Актуальные решения и спорные места экономики зафиксированы в [`docs/economy-decisions.md`](docs/economy-decisions.md).

## 5. Карта образовательного контента

| Тема | Навык | Реализация |
|---|---|---|
| Планирование бюджета | распределить ограниченный ресурс | экран периода и `validateBudgetPlan` |
| Обязательное и желаемое | приоритизировать необходимое | каталог покупок и события |
| Накопления | откладывать на цель | `PiggyBank`, финансовые цели |
| Покупки и последствия | сравнить цену, баланс и эффект | подтверждение и feedback |
| Ошибка как учебная ситуация | понять причину и восстановиться | объяснение результата, повтор периода |

Минимум контента ТЗ (6 заданий по 3 темам, 8 покупок двух типов, 3 цели, 3 стадии) следует проверять отдельным чек-листом перед финальной сдачей; текущий каталог шире, но часть контента ещё требует экспертной сверки.

## 7. UX/UI и доступность

Интерфейс mobile-first, портретный, с крупными touch-зонами, короткими фразами и визуальными последствиями. Цвет не используется как единственный носитель смысла: применяются подписи, иконки и текст результата. Звуки, музыка, вибрация и голосовые подсказки можно отключить. Действия, меняющие баланс, накопления или прогресс, проходят через подтверждение.

Сильная сторона UX — связь «решение → изменение кошелька/накоплений → состояние питомца». Ограничение текущего прототипа — доступность и масштабирование шрифта нужно дополнительно прогнать на физическом устройстве и зафиксировать в отчёте.

## 8. Разрешения и данные

Приложение не запрашивает аккаунт, реальное имя ребёнка, телефон, e-mail, банковские данные, камеру, микрофон, контакты или геолокацию. В Android-манифесте оставлены `INTERNET` и `VIBRATE`; последний нужен для виброотклика. Профиль хранится локально; взрослый может удалить или сбросить его из защищённого раздела. Секреты, токены и ключи подписи в репозитории отсутствуют.

## 9. Тестирование

```bash
npm run test:economy
```

Проверяются валидность бюджета, отказ при нехватке средств, покупки, расчёт результата периода, накопления, стадии развития и связность событий пяти периодов. Перед финальной сдачей нужен ручной протокол: первый запуск, 360 dp, закрытие/повторный запуск, сброс взрослым, отсутствие сети, debug/release APK и физическое устройство с моделью, Android, RAM и результатом.

## 10. Сильные стороны

- цельный игровой цикл вместо набора тестов;
- детерминированная и отдельно тестируемая экономика;
- локальная работа без регистрации и сбора персональных данных;
- контент отделён от интерфейса и расширяется через данные;
- Android-контейнер уже подготовлен через Capacitor;
- сохранение состояния и демонстрационные переходы предусмотрены.

## 11. Ограничения и план развития

Это конкурсный прототип, а не готовый массовый релиз. Нужны финальная сверка минимального объёма контента ТЗ, полное прохождение обязательного сценария на физическом устройстве, подписанный release APK, проверка лицензий ассетов и устранение неоднозначностей в экономике (перенос остатка, доход периода, правила повторения). Следующий этап — больше независимых сценариев, автоматический тест пользовательского пути, аналитика без персональных данных и карточка RuStore.

# Документация FunnyMoney для комиссии хакатона

## Назначение проекта

FunnyMoney, рабочее название «Питомец Финни», - офлайн-ориентированная обучающая игра для детей 7-11 лет. Ребёнок заботится о виртуальном питомце, зарабатывает игровые монеты, планирует бюджет, выбирает между необходимыми и желаемыми покупками, копит на цель и видит последствия решений. Реальные деньги, платежи, реклама и обязательная регистрация не используются.

Документ описывает представленный прототип, запуск, архитектуру, экономику и соответствие требованиям ТЗ.

## 2. Android окружение и сборка релиза

Проект использует React, TypeScript, Vite и Capacitor 8. Рекомендуемое окружение: Node.js 22, JDK 21, Android SDK API 35, Android Build Tools 35 и актуальная стабильная версия Android Studio. Точные версии JavaScript-зависимостей зафиксированы в `package-lock.json`.

```bash
npm ci
npm run build
npx cap sync android
cd android
./gradlew assembleDebug
```

Debug APK появляется в `android/app/build/outputs/apk/debug/`. Release APK собирается с закрытым keystore, который не хранится в репозитории:

```bash
./gradlew assembleRelease
```

Текущие параметры Android: `applicationId com.funnymoney.app`, версия `1.0`, номер сборки `1`. Перед сдачей нужно зафиксировать checksum подписанного APK, расположение ключа вне Git, модель устройства, версию Android и фактический номер сборки.

## 3. Архитектура

```text
Android APK (Capacitor)
  -> WebView
    -> React + TypeScript + Vite
      -> хранилища и экраны модулей
        -> чистые правила Game Core
          -> Capacitor Preferences / веб-fallback
```

Основные модули: профиль и питомец, кошелёк и экономика, периоды и планирование бюджета, покупки, уроки и практика, сюжетные события, мини-игра, прогресс и родительские настройки. Серверная часть в прототипе отсутствует. OpenAPI не требуется, так как основной игровой цикл работает локально.

## 4. Данные и сохранение

Локальный профиль хранит имя и персонажа питомца, состояние питомца, инвентарь, кошелёк, настройки, состояние обучения и прогресс. Состояние периода содержит номер периода, баланс, план бюджета, фактические расходы, накопления, награды, статус и историю завершённых периодов. Уроки, товары, цели и события описаны типизированными записями в `src/data/` и `src/features/periodEvents/eventData.ts`.

На Android используется `@capacitor/preferences`, веб-версия использует резервное локальное хранилище. Ключи имеют префикс `funnymoney:` и версию схемы. Аккаунт, электронная почта, телефон, платёжные данные, камера, микрофон, контакты и геолокация не требуются.

## 6. Правила и формулы экономики

- План действителен, если все три категории неотрицательны, а их сумма не превышает доступный баланс.
- Покупка разрешена только при наличии товара, положительной цене и достаточном балансе кошелька.
- Накопления переводятся отдельным подтверждённым действием и не смешиваются с кошельком автоматически.
- Совпадение плана и факта: `100 x (1 - сумма абсолютных отклонений / сумма плана)`, результат ограничивается диапазоном 0-100.
- Итог периода объединяет обязательные расходы, совпадение плана и факта и регулярность накоплений согласно `src/core/economy.ts`.
- Если правило периода включено, бонус накоплений в конце периода составляет 20 процентов.
- Стадия питомца повышается после успешных периодов и является учебным игровым индикатором.

Журнал решений и нерешённые вопросы находятся в `docs/economy-decisions.md`.

## 7. Карта образовательного контента

| Тема | Навык ребёнка | Реализация в игре | Объяснение ребёнку |
|---|---|---|---|
| Планирование бюджета | Распределить ограниченный ресурс | Экран периода и проверка бюджета | «Реши, что нужно купить, что хочется, а что лучше отложить». |
| Нужное и желаемое | Ставить важные потребности первыми | Магазин и сюжетные события | «Сначала позаботься о важном. Желания можно выполнить, если монет хватает». |
| Накопления | Откладывать постепенно на цель | Копилка и прогресс цели | «Даже маленький взнос приближает тебя к цели». |
| План и факт | Сравнить план с результатом | Практика в уроках 5 и 6 | «Посмотри, совпал ли план с тем, что получилось». |
| Последствия | Связать решение с результатом | Обратная связь событий и состояние питомца | «Решение изменило кошелёк и состояние Мишки». |

## 8. UX и доступность

Интерфейс рассчитан на портретный мобильный экран. Используются крупные touch-зоны, короткие фразы, иконки вместе с подписями и немедленная обратная связь. Цвет не является единственным носителем смысла: успех и ошибка дополнительно показываются текстом, иконкой и звуком. Музыку, звуки, озвучку и анимации можно отключить. Действия, меняющие кошелёк, накопления или прогресс, подтверждаются там, где это необходимо. Тексты не стыдят и не пугают ребёнка.

Перед сдачей нужны проверка на физическом устройстве при ширине 360 dp и больше, системное увеличение текста, проверка доступности и подтверждение удобства всех touch-зон.

## 9. Разрешения, приватность и удаление данных

Приложение использует только необходимые разрешения: сетевой доступ для сценариев разработки и развёртывания и вибрацию для тактильного отклика. Камера, микрофон, геолокация, контакты, Bluetooth и платёжные разрешения не нужны. Профиль хранится локально. Взрослый может сбросить и удалить локальный профиль из защищённого раздела. Секреты, токены и ключи подписи не должны попадать в Git.

## 10. Тест-кейсы и отчёт с устройства

Автоматические проверки:

```bash
npm run test:economy
npm run build
```

Ручные тест-кейсы:

1. Первый запуск -> создать локальный профиль -> перезапустить -> профиль сохранился.
2. Задать корректный бюджет -> некорректная сумма отклоняется с понятным объяснением.
3. Купить товар при достаточном балансе -> баланс и эффект питомца меняются один раз.
4. Купить товар без достаточного баланса -> отрицательного остатка и частичной покупки нет.
5. Перевести накопления -> только подтверждённый перевод меняет накопления.
6. Открыть событие -> выбрать вариант -> обратная связь соответствует выбранному варианту.
7. Ошибиться в уроке -> после последнего задания открывается работа над ошибками.
8. Нажать «Проверить» без попытки -> ошибка не записывается.
9. Отключить голос, музыку и анимации -> настройки сохраняются после переходов.
10. Открыть раздел взрослого -> посмотреть прогресс -> сбросить локальный профиль.

Отчёт с физического устройства нужно заполнить перед сдачей: модель телефона, версия Android, оперативная память, версия APK, время запуска, работа без сети, сохранение после перезапуска, экран 360 dp, доступность и найденные дефекты. Этот документ не выдаёт непроведённую проверку за проведённую.
